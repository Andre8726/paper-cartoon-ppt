# 可编辑 PPT 的制作与检查

## 选择运行环境

先检查现有工具和库；在 Codex 桌面可使用 `load_workspace_dependencies` 查找运行时。常见路径是 python-pptx 或 PptxGenJS；选择当前可用且能实现所需自由曲线、分组和连接线的方案。不要在缺少依赖时反复重装环境或自动启动可见 PowerPoint 窗口。

默认一页横向画布；根据论文关系选择合适比例，用户给定的尺寸优先。绘图的主交付是科学示意图，不添加演示文稿封面、导航或装饰性总结页。

## 构建原则

- 用统一的坐标和样式常量控制配色、描边、字号及层次；将生成脚本保存至输出的 `build/`。
- 为重复的科研对象创建可复用绘制函数，例如细胞、反应容器、颗粒或实验装置。部件由原生形状/自由曲线组成，每个对象单独分组，必要时可取消组合继续编辑。
- 这些函数随具体论文建立；不要为了准备技能而提前维护一个与实际用途无关的庞大图标库。
- 关系线有明确端点和方向；可以使用绑定到对象的连接线时优先绑定。明确叠放顺序，避免箭头被主体遮住或穿过标签。
- 以短标签表达科学对象，保留必要的单位、希腊字母和上下标；缩写过多时给简短图例。
- 用位置、线型及文字共同编码关键差异，不能只依赖红绿颜色。
- 不修改参考图后塞入输出，不将参考图当作生成脚本的素材依赖。

## 验证

1. 用库重新读取或检查 PPTX 的 OOXML 包：幻灯片数量符合要求；主要标签存在；形状及分组有效；关键内容不是一张 picture 或 graphic frame。结构解析只能证明文件结构，不能代替视觉检查。
2. 使用实际可用的渲染器将最终 PPTX 渲染为 PNG/PDF，例如现有幻灯片渲染工具、LibreOffice 或可用的 PowerPoint 导出接口。保持输出来源可追溯。若只有 PDF 渲染结果，再将相应页面转为 PNG。
3. 查看全图和局部放大：科学对象可辨识、线条连续、箭头无误、标签不遮挡、无越界，颜色与线条一致。修改后重新渲染最终版本。
4. 与参考图并排查看：允许通用配色和描边风格相近，检查是否复用了独特构图和轮廓。发现问题后根据论文重新设计对应部分。
5. 再对照证据映射检查科学准确性。视觉简洁不能以省略关键条件或夸大因果为代价。

若当前环境无法渲染，报告“PPTX 已生成，最终渲染与视觉核验未完成”，并保留源文件。不得把独立程序绘制的近似图当作最终 PPTX 的核验结果。
